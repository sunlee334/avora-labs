## 어떻게 쟀나

`.stickyCta` 는 스크립트가 `data-shown="true"` 를 붙여야 올라옵니다. 측정에서는
그 속성을 직접 세우고 한 프레임 뒤에 쟀습니다.

그리고 이 바는 **알림 신청을 받는 동안에만** 존재합니다(`!CAN_ORDER`). 기본
빌드(커머스)에는 바가 없어 처음에 "바 없음" 만 다섯 줄 나왔습니다.
`PUBLIC_CHECKOUT_MODE=external` 로 다시 빌드해야 나옵니다.

잘림 판정은 눈이 아니라 `scrollWidth > clientWidth` 로 했습니다 —
`text-overflow` 없이 넘치면 눈으로는 멀쩡해 보이는 경우가 있습니다.

시트) 쓰이므로 세 곳 모두 짧아집니다.

## 전면 스윕

4개 화면(홈 · 제품 · 브랜드 · 검증단) × ko·vi × WebKit·Chromium = **16조합**,
매번 새 컨텍스트로 하드 리로드.

| 항목 | 결과 |
|---|---|
| 가로 넘침 | 0 |
| 글자 입력칸 `font-size` < 16px | 0 (iOS 자동 확대 없음) |
| 탭 영역 < 44×44 | 0 |
| 버튼·링크 라벨 잘림 | 0 |

### 첫 판정 4건은 오탐이었다

처음 돌렸을 때 `/panel` 에서 "11px 입력칸 10개" 가 걸렸습니다. 열어 보니
**라디오·체크박스와 봇 함정(허니팟)** 이었습니다.

- iOS 자동 확대는 **글자를 치는 칸** 에만 걸립니다. 라디오·체크박스는 아닙니다
- `name="website"` 는 화면 밖으로 밀어낸 봇 함정입니다(`aria-hidden`).
  사람이 닿지 않습니다

판정 조건을 좁혀 다시 돌렸고 16조합 전부 통과합니다. **수치가 나왔다고 결함이
아닙니다 — 무엇을 잰 것인지 봐야 합니다.**
